# RPiDuino 0.1.5 · Pi 3B+ 的 XDOS V2 操作與驗證

## 安裝與建置

1. 在 Arduino IDE 的「額外的開發板管理員網址」加入 [RPiDuino 板卡索引](https://raw.githubusercontent.com/hypersolver/RPiDuino/main/package_rpiduino_index.json)，從開發板管理員安裝 **RPiDuino 0.1.5**。
2. 依[主指南](../README.md)安裝 ARM 工具鏈，並在 Ubuntu／WSL 安裝 `python3-pyelftools`。使用 UART 上傳時，在執行上傳工具的 Python 環境安裝 `pyserial`。
3. 從 [0.1.5 Release](https://github.com/hypersolver/RPiDuino/releases/tag/v0.1.5) 下載 `fvcore2-host.zip` 與 `SHA256SUMS.txt`。用 `sha256sum -c SHA256SUMS.txt` 或 PowerShell `Get-FileHash -Algorithm SHA256` 核對 ZIP。解壓後，把 `RPIDUINO_XDOS_V2_HOST` 設為包含 `kernel.elf`、`kernel.img` 和 `headers/` 的資料夾，再重啟 IDE。
4. Pi 3B+ 開機使用配對的 [FVCORE2 核心](https://github.com/hypersolver/raspberry-pi-xdos/releases/tag/v0.6.2-rc3-xapp6-fvcore2)。選 **RPiDuino 3/3B+ → Build target → XDOS XAPP V2**，再選擇 **Sketch CPU**。V2 XAPP 需與核心配對。
5. **XAPP Screen** 選 **None**（預設）、**Window** 或 **Full**。建置目錄會產生 `.APP`。手動安裝時，依清單中的檔名將 XAPP 放入 `XDOS/INBOX`。若透過 UART 上傳，工具會以實際傳輸檔名更新清單。將清單複製至 `XDOS/APPS` 並重開 XDOS，桌面即可顯示捷徑。

CPU0 沿用原本的 `delay()`，借用核心上的 `delay()` 會呼叫 XDOS 的睡眠 API，並可因關閉請求提前返回。草稿可在返回後呼叫 `rpiduino_xdos_stop_requested()`，收到停止時從 `loop()` 返回，以便 XDOS 回收資源。

## Pi 3B+ 實測紀錄

- CPU3 的 Arduino 草稿執行 10 次 `delay(100)`，共 **1,001.119 ms**，單次最長 **100.126 ms**。名義 5,000 ms 的延遲收到關閉請求後提前返回，當時已睡眠 **11.759 ms**，工作核心與槽位均釋放。
- FVCORE2 在 1920×1080 實測四份 SD 清單。從桌面點擊 None、Window 與第一個 Full 均成功，第二個 Full 回 `-11`。測試捷徑已移出桌面，原有捷徑已還原。
- 測完切回 FVMNET2，開機標籤與 UART PING READY 通過，序列埠已釋放。
