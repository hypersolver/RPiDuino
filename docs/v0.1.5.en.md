# RPiDuino 0.1.5 · XDOS V2 on Raspberry Pi 3B+

## Install and build

1. Add the [RPiDuino Boards Manager index](https://raw.githubusercontent.com/hypersolver/RPiDuino/main/package_rpiduino_index.json) in Arduino IDE's Additional Boards Manager URLs. Install **RPiDuino 0.1.5**.
2. Install `python3-pyelftools` in Ubuntu or WSL in addition to the ARM toolchain in the [main guide](../README.en.md). For UART upload, install `pyserial` in the Python environment that runs the uploader.
3. Download `fvcore2-host.zip` and `SHA256SUMS.txt` from the [0.1.5 release](https://github.com/hypersolver/RPiDuino/releases/tag/v0.1.5). Check the ZIPs using `sha256sum -c SHA256SUMS.txt` or PowerShell `Get-FileHash -Algorithm SHA256`. Extract the host kit and point `RPIDUINO_XDOS_V2_HOST` at the folder containing `kernel.elf`, `kernel.img` and `headers/`. Restart Arduino IDE after setting the variable.
4. Boot the matching [FVCORE2 host on Pi 3B+](https://github.com/hypersolver/raspberry-pi-xdos/releases/tag/v0.6.2-rc3-xapp6-fvcore2). Select **RPiDuino 3/3B+ → Build target → XDOS XAPP V2** and choose **Sketch CPU**. The V2 XAPP is bound to the matching kernel.
5. Set **XAPP Screen** to **None** (default), **Window**, or **Full**. The build generates an `.APP` sidecar in the build directory. For manual installation, put the XAPP under its generated filename in `XDOS/INBOX`. After UART upload, the sidecar is updated to use the transferred filename. Copy the sidecar into `XDOS/APPS` and restart XDOS to show its desktop shortcut.

CPU0 uses the original Arduino `delay()`. A borrowed core sleeps via the XDOS API, and `delay()` can return early on a close request. A worker sketch can check `rpiduino_xdos_stop_requested()` and return from `loop()` so that XDOS can reclaim its resources.

## Pi 3B+ test record

- An Arduino CPU3 probe executed ten `delay(100)` calls in **1,001.119 ms**. The longest call lasted **100.126 ms**. Closing the app interrupted a nominal 5,000 ms delay after **11.759 ms** of elapsed sleep and released the worker core and slot.
- Four generated SD manifests were tested from the FVCORE2 desktop at 1920×1080. None, Window and the first Full launch succeeded. The second Full launch returned `-11`. The test shortcuts were moved out of the desktop directory and the original shortcuts restored.
- The Pi was returned to FVMNET2. The boot banner and UART PING READY were verified, and the serial port was released.
